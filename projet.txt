1. PRESENTATION GENERALE
================================================================================

CERBERE est un systeme de controle d'acces intelligent deploye au Lycee Joseph
Gaillard. Il repose sur 3 Raspberry Pi interconnectes en reseau local (WiFi),
une base de donnees MySQL centralisee, un site web d'administration, une
application mobile iOS, une application macOS et une application Apple Watch.

Le systeme gere :
- L'ouverture/fermeture de porte par badge RFID
- L'ouverture a distance depuis le site web, l'application mobile ou la montre
- La detection de presence par capteur PIR
- La surveillance video en direct par camera
- La journalisation de tous les acces et evenements
- La gestion des utilisateurs, badges et autorisations

3. COMMUNICATIONS ENTRE COMPOSANTS
================================================================================

3.1 Verification d'acces par badge RFID
------------------------------------------------------------------------
[Badge RFID] --UART--> [Pi RFID (192.168.1.49)]
                              |
                              | HTTP POST /api/badge_check.php
                              | Corps: {"uid": "XXXX", "id_porte": 1}
                              v
                        [Serveur (192.168.1.199)]
                              |
                              | Verification en base de donnees :
                              | - Badge existe et actif ?
                              | - Badge non perdu / non expire ?
                              | - Utilisateur actif ?
                              | - Autorisation pour cette porte ?
                              | - Jour et horaire autorises ?
                              |
                              | Reponse: {"autorise": true/false,
                              |           "type_evenement": "acces_accorde"}
                              v
                        [Pi RFID (192.168.1.49)]
                              |
                              | Si autorise : commande I2C
                              | Bus 1, Adresse 0x20, Registre 0x06
                              v
                        [Relais PCA9554]
                              |
                              +-- Canal 1 : Gache electrique (ouvre)
                              +-- Canal 2 : Ventouse magnetique (relache)
                              |
                              | Apres X secondes : referme automatiquement


3.2 Ouverture a distance (site web / app mobile / Apple Watch)

[Navigateur/App] --HTTP POST--> [Serveur (192.168.1.199)]

                                         | HTTP POST vers Pi RFID
                                         | http://192.168.1.49:5000/ouvrir

                                         |

6. SCRIPTS PYTHON
================================================================================

6.1 badge_bdd.py (Pi RFID - 192.168.1.49)
------------------------------------------------------------------------
- Lecture badges RFID via port serie /dev/ttyS0 (9600 bauds)
- Mode enregistrement : 5 lectures pour valider un badge
- Mode lecture : verification avec similarite > 85%
- Anti-rebond : delai de 2 secondes entre lectures
- Cache badges : 60 secondes pour eviter les requetes repetees
- Appel API badge_check.php pour verification
- Ouverture porte via gache.py si autorise

6.2 door_api.py (Pi RFID - 192.168.1.49)
------------------------------------------------------------------------
- Serveur HTTP sur port 5000
- Endpoint POST /ouvrir avec authentification par secret
- Execute gache.py en sous-processus
- Endpoint GET /status pour monitoring

6.3 gache.py (Pi RFID - 192.168.1.49)
------------------------------------------------------------------------
- Controle relais I2C via PCA9554
- Bus I2C : 1
- Adresse peripherique : 0x20
- Registre de sortie : 0x06
- Canal 1 (bit 0) : gache electrique
- Canal 2 (bit 1) : ventouse magnetique
- Options : --ouvrir, --fermer, --duree N

6.4 detection.py (Pi Presence - 192.168.1.89)
------------------------------------------------------------------------
- Capteur PIR sur GPIO 17
- LED de statut sur GPIO 18
- Mesure la duree de chaque detection
- Seuil d'alerte : 30 secondes
- Envoi des detections au serveur via API
- Capture camera automatique lors d'une alerte

6.5 camera_stream.py (Pi Camera - 192.168.1.138)
------------------------------------------------------------------------
- Capture via rpicam-vid (codec MJPEG, 640x480, 15fps)
- Rotation 180 degres via Pillow (camera montee a l'envers)
- Serveur HTTP sur port 8090
- /stream : flux MJPEG continu (multipart/x-mixed-replace)
- /snapshot : capture JPEG unique
- Headers CORS pour acces cross-origin

13. DEPLOIEMENT
================================================================================

Les fichiers sont deployes sur les Pi via SSH/SCP :

  Mac (local) --> SCP vers /tmp sur le Pi --> sudo cp vers destination finale

Permissions des fichiers web :
  chmod 644 fichiers
  chown www-data:www-data /var/www/html/*

Activation des services :
  sudo systemctl enable nom-du-service
  sudo systemctl start nom-du-service

Les 3 Raspberry Pi demarrent automatiquement tous les services
au boot grace aux fichiers .service dans /etc/systemd/system/

Adresses IP statiques configurees via NetworkManager (nmcli).
